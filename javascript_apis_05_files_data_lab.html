Blob — バイナリデータの基本単位 (型/サイズ/slice)

✓ iOS ✓ Android

Blob は「型 (MIME) を持った不変のバイナリ塊」。文字列・ArrayBuffer・TypedArray などを材料に new Blob([...], {type:...}) で作る。slice() で部分切り出し、size と type で内容を確認できる。

💡 利用シーン
  1. CSV/JSON文字列を Blob 化 → ダウンロードリンク経由で保存
  2. 大きいファイルを slice で分割 → チャンクアップロード (Tom が以前やった案件)
  3. Canvas や FileReader 等の API 間でバイナリを受け渡す共通コンテナ
  Blob = 不変のバイナリ塊
  ┌────────────────────────────┐
  │  parts:  ['hello,', 'world']
  │  type:   'text/plain'      │
  │  size:   11 bytes          │
  └────────────────────────────┘
        │
        ▼  blob.slice(0, 5, 'text/plain')
  ┌────────────────────────────┐
  │  ['hello'] / 'text/plain'  │
  │  size: 5                   │
  └────────────────────────────┘
📌 OutSystems文脈での旨味: 帳票エクスポート(CSV/Excel)時、サーバから Base64 で受けた文字列を Blob 化 → createObjectURL で <a download> に渡せば、Server Action 不要でブラウザ完結のダウンロードが実現できる。

File — Blob 拡張、input type=file から取得

✓ iOS ✓ Android

File は Blob のサブクラス。name と lastModified が追加されているだけで、それ以外は Blob と同じ API (slice / text / arrayBuffer / stream)。<input type="file"> から files[i] で取れる。

💡 利用シーン
  1. ユーザがアップロードする画像/CSV/PDF をクライアント側で確認
  2. ファイル名/サイズ/MIME型 でクライアントバリデーション
  3. 選択された複数ファイルを 1つずつ FileReader で読む
  File extends Blob
  ┌──────────────────────────────────┐
  │  Blob のプロパティ:              │
  │    .size, .type                  │
  │    .slice(), .text(), .stream()  │
  │  + File 固有プロパティ:          │
  │    .name           ← 'photo.jpg' │
  │    .lastModified   ← 1714560000  │
  └──────────────────────────────────┘
        ▲
        │ <input type="file">.files[0]

FileReader — Blob/File を3形式で読む (Text / DataURL / ArrayBuffer)

✓ iOS ✓ Android

古典的な非同期読み込み API。readAsText で文字列、readAsDataURL で base64 込みの data: URL、readAsArrayBuffer でバイナリそのままを取り出せる。完了は onload イベントで受ける。最近は Blob.text() / arrayBuffer() で代替できることも多い。

💡 利用シーン
  1. 選択された画像を data:URL に変換 → <img src> でプレビュー
  2. CSV を文字列で読んで内容パース
  3. バイナリの先頭バイト (マジックナンバー) を見て本当に PDF か検証
  FileReader: 3形式の読み出し
  ┌─────────────────────────────────────┐
  │ readAsText(blob, 'utf-8')           │
  │   → result: "hello, world"          │
  ├─────────────────────────────────────┤
  │ readAsDataURL(blob)                 │
  │   → result: "data:text/plain;base64,│
  │              aGVsbG8sd29ybGQ="      │
  ├─────────────────────────────────────┤
  │ readAsArrayBuffer(blob)             │
  │   → result: ArrayBuffer(11)         │
  │      [0x68 0x65 0x6c 0x6c 0x6f ...] │
  └─────────────────────────────────────┘
   onload で result を取り出す (非同期)
📌 OutSystems文脈での旨味: OutSystems の BinaryData は Server 側で扱うが、Client Action から JS で FileReader を使えば、サーバ往復ゼロで「画像プレビュー → ユーザOK後にアップロード」のUXが組める。サーバ負荷も帯域も削減。

function lab3Run() {
  clearLog('lab3-log');
  const blob = new Blob(['hello,world'], { type: 'text/plain' });

  // [1] readAsText
  const r1 = new FileReader();
  r1.onload = () => console.log('Text:', r1.result);
  r1.readAsText(blob, 'utf-8');

  // [2] readAsDataURL
  const r2 = new FileReader();
  r2.onload = () => console.log('DataURL:', r2.result);
  r2.readAsDataURL(blob);

  // [3] readAsArrayBuffer → 先頭5バイトを 16進で表示
  const r3 = new FileReader();
  r3.onload = () => {
    const u8 = new Uint8Array(r3.result);
    const hex = [...u8.slice(0, 5)].map(b => b.toString(16).padStart(2, '0')).join(' ');
    console.log('ArrayBuffer head5(hex):', hex);
  };
  r3.readAsArrayBuffer(blob);
  setBA('lab3', 'Blob 1個', '同一Blobを3形式で取り出し');
}

URL.createObjectURL — Blob を blob: URL に変換 / revoke で解放

✓ iOS ✓ Android

Blob を一意の blob:https://... URL に変換する。<img src>, <a href download>, <video src> などにそのまま渡せる。使い終わったら revokeObjectURL で必ず解放しないと、Blob がメモリに居座り続けてリークする。

💡 利用シーン
  1. 選択画像のプレビュー (DataURL より高速・省メモリ)
  2. サーバから Blob で取得した PDF を新タブで開く
  3. 動的生成した CSV/Excel を <a download> でダウンロード
  ライフサイクル: 必ず revoke
  ┌─────────────────────────────────┐
  │  const url = createObjectURL(blob)
  │     ↓ blob:https://example/abc-123
  │  <img src=url>  ← 表示          │
  │     ↓ 表示完了                   │
  │  img.onload = () =>             │
  │     URL.revokeObjectURL(url)    │
  │     ↓                           │
  │  メモリ解放 ✓                   │
  └─────────────────────────────────┘
   revokeしないと blob: が永遠に残る
📌 OutSystems文脈での旨味: BinaryData → Server-side で base64文字列を Client に返却 → JS で Blob化 → createObjectURL で <a download> に。これだけで「Server Action でファイルを返す」より高速 (再ロード不要) かつスマホでもダウンロードが安定する。

ArrayBuffer / TypedArray / DataView — 生バイナリ操作の3層

✓ iOS ✓ Android

ArrayBuffer は「型のない素のバイト列」。直接アクセスはできず、ビュー (Uint8Array, Float32Array...) または DataView を被せて読み書きする。TypedArray は同じ型での連続アクセス向き、DataView はバイトオーダー (endianness) を意識した混在型読み書き向き。

💡 利用シーン
  1. WebSocket / fetch で受けたバイナリプロトコルをパース
  2. PNG/JPEG のヘッダ先頭バイトを見てMIME検証
  3. WASM や Canvas (ImageData) との高速データ受け渡し
  3層モデル
  ┌─────────────────────────────────────┐
  │ ArrayBuffer (16 bytes 確保)         │
  │ [00 00 00 00 00 00 00 00            │
  │  00 00 00 00 00 00 00 00]           │
  └─────────────────────────────────────┘
       ▲                      ▲
       │ 同じバッファに2つの  │
       │ ビューを被せられる   │
  ┌─────────────┐      ┌──────────────┐
  │ Uint8Array  │      │ Float32Array │
  │ 16要素 (1B) │      │ 4要素 (4B)   │
  │ [0..255]    │      │ [浮動小数点] │
  └─────────────┘      └──────────────┘
                       ┌──────────────┐
                       │ DataView     │
                       │ 任意offset+型│
                       │ +endian指定  │
                       └──────────────┘
📌 OutSystems文脈での旨味: OutSystems Extension で C# が返す byte[] を JS 側で受けるとき、ArrayBuffer → Uint8Array に被せれば配列のように扱える。VB.NET の Byte() 配列ともメモリレイアウトが対応するので、バイナリプロトコル設計のメンタルモデルを揃えやすい。

function lab5Run() {
  clearLog('lab5-log');
  const buf = new ArrayBuffer(16);  // 16バイト確保
  console.log('byteLength:', buf.byteLength);

  // [1] Uint8Array でビュー → 1バイトずつ書き込み
  const u8 = new Uint8Array(buf);
  u8[0] = 0x48; u8[1] = 0x69;  // 'H', 'i'
  console.log('u8[0..2]:', Array.from(u8.slice(0, 2)));

  // [2] DataView で 4バイト目に Int32 (Big Endian) を書く
  const dv = new DataView(buf);
  dv.setInt32(4, 0x01020304, false);  // false = BigEndian
  console.log('byte[4..8]:', Array.from(u8.slice(4, 8)).map(b => b.toString(16)));

  // [3] DataView で同じ位置を Little Endian で読む → 値が逆転
  const leVal = dv.getInt32(4, true);
  console.log('LE で読むと:', '0x' + leVal.toString(16));
  setBA('lab5', '16B のゼロ埋めバッファ', 'Hi + Int32 を埋めた状態');
}

structuredClone — 真の deep copy (循環参照・Map/Set もOK)

✓ iOS 15.4+ ✓ Android

JSON.parse(JSON.stringify(x)) では取りこぼす Date/Map/Set/RegExp/ArrayBuffer/循環参照まで、構造化複製アルゴリズムで正しく深くコピーする標準API。Node.js 17+ / 主要ブラウザで利用可。

💡 利用シーン
  1. state を一切共有しないで丸ごと複製 (Redux 風の不変更新)
  2. Date や Map を含むキャッシュ/設定オブジェクトのスナップショット
  3. postMessage の送信前検証 (clone 可能なら postMessage も通る)
  3手法 比較表
  ┌──────────────────┬──────┬──────┬──────┐
  │ 手法              │ Date │ Map  │ 循環  │
  ├──────────────────┼──────┼──────┼──────┤
  │ Object.assign({}) │ 浅い │ 浅い │ 浅い │
  │ {...obj} スプレッド│ 浅い │ 浅い │ 浅い │
  │ JSON.parse(JSON…)│ ✗string│ ✗{} │ ✗例外│
  │ structuredClone  │ ✓    │ ✓    │ ✓    │
  └──────────────────┴──────┴──────┴──────┘
  注: 関数 / DOM / Symbol は clone不可 (例外)
📌 OutSystems文脈での旨味: Wijmo CollectionView の元データを一時編集→キャンセルで戻したい場合、ロード時に structuredClone で「原本」を取っておけば、commitEdit/cancelEdit を待たずに任意のタイミングで完全復元できる。Date 列が string化されない点が JSON.parse 方式より優秀。

JSON.stringify/parse 応用 — replacer / reviver / BigInt 対応

✓ iOS ✓ Android

JSON.stringify(value, replacer, space) と JSON.parse(text, reviver)。第2引数で「シリアライズ時にキー/値を加工する関数」、parse 側では「復元時にDateや BigInt に戻す関数」を渡せる。BigInt は標準では throw するので replacer で文字列化が定石。

💡 利用シーン
  1. パスワード/トークン等の機密フィールドを除外して送信
  2. "2025-01-01T00:00:00Z" を JSON.parse で自動 Date 化
  3. BigInt を含むデータを JSON 化 (普通は throw する)
  シリアライズ パイプライン
  ┌──────────┐   replacer    ┌────────┐
  │ オブジェクト│ ───────→     │ 加工後  │
  └──────────┘  各(k,v)で呼び  └────────┘
                  返り値が       │
                  実際にJSONに   │ stringify
                                 ▼
                          "{"name":"...",...}"
                                 │ parse
                                 ▼
                          ┌────────┐
                          │ 加工後  │
                          └────────┘
                            ▲
                            │ reviver で復元
                          (例: ISO文字列 → Date)
📌 OutSystems文脈での旨味: REST API の JSONOutput / JSONInput の OnAfterResponse / OnBeforeRequest で、共通的に「Decimal を文字列化」「null を空文字に」等のフィルタを噛ませたい場合、JS 経由の場合は replacer/reviver で集中処理できる。Server Action 側のシリアライザ拡張より軽量。

function lab7Run() {
  clearLog('lab7-log');

  // [1] replacer: password キーを除外
  const user = { name: 'tom', password: 'secret', age: 40 };
  const safe = JSON.stringify(user, (k, v) => k === 'password' ? undefined : v);
  console.log('安全版:', safe);

  // [2] reviver: ISO文字列 → Date 復元
  const text = '{"when":"2025-01-01T00:00:00Z","name":"tom"}';
  const obj = JSON.parse(text, (k, v) => {
    if (typeof v === 'string' && /^\d{4}-\d{2}-\d{2}T/.test(v)) return new Date(v);
    return v;
  });
  console.log('復元 when 型:', obj.when.constructor.name);  // Date

  // [3] BigInt: replacer で文字列化、reviver で復元
  const data = { id: 9007199254740993n };  // Number 限界超
  const json = JSON.stringify(data, (k, v) =>
    typeof v === 'bigint' ? v.toString() + 'n' : v);
  console.log('BigInt JSON:', json);
  const back = JSON.parse(json, (k, v) =>
    typeof v === 'string' && /^\d+n$/.test(v) ? BigInt(v.slice(0, -1)) : v);
  console.log('復元 id:', back.id, typeof back.id);  // bigint
  setBA('lab7', '生オブジェクト3種', 'replacer/reviver で加工済み');
}

BigInt — 任意精度整数 (123n リテラル / Number との非互換)

✓ iOS ✓ Android

Number は IEEE 754 で 2^53-1 (Number.MAX_SAFE_INTEGER) を超えると精度が落ちる。BigInt は末尾 n リテラルか BigInt(...) で生成する任意精度の整数型。Number と直接の算術はできない (TypeError)。

💡 利用シーン
  1. RDB の bigint / Java/.NET の long をフロントで丸めずに扱う
  2. 暗号関連の大きな素数・モジュロ演算
  3. UNIXミリ秒のさらに細かいタイムスタンプ (高精度ID等)
  Number vs BigInt
  ┌──────────────────────────────────────┐
  │ Number.MAX_SAFE_INTEGER              │
  │   = 2^53 - 1 = 9007199254740991      │
  │ → これを超えると精度欠落             │
  │                                      │
  │   9007199254740993       ← Number    │
  │ ≠ 9007199254740993n      ← BigInt    │
  │                                      │
  │ 9007199254740993 === 9007199254740992│
  │   // true!! (Number は丸める)        │
  └──────────────────────────────────────┘
  混在禁止: 1n + 1 → TypeError
📌 OutSystems文脈での旨味: Azure SQL の bigint 列 (例: 採番ID) を Server Action で Long に乗せて返却 → JSON 化されるとき Number 範囲を超えると JS 側で値が壊れる。文字列化して送り、フロントで BigInt 化して比較すれば桁落ちゼロ。

Intl.NumberFormat / DateTimeFormat — 通貨・日付の国際化

✓ iOS ✓ Android

ロケール (ja-JP / en-US / ...) と オプション (style / currency / dateStyle ...) を渡すだけで、3桁区切り・通貨記号・年月日順序などを自動でローカライズ。手書きの format 関数を撲滅できる ECMA-402 仕様。

💡 利用シーン
  1. 金額表示を ja-JP は「¥1,000」、en-US は「$1,000」

    }
  });

  await readable.pipeThrough(upper).pipeTo(writable);

SubtleCrypto.digest — SHA-256 ハッシュ (ファイル整合性検証)

✓ iOS ✓ Android ⚠ HTTPS/localhost必須

crypto.subtle.digest('SHA-256', buffer) で ArrayBuffer のハッシュを ArrayBuffer で得る非同期 API。Hex文字列にしたければ Uint8Array に被せて 16進化。secure context (https または localhost) のみ動作。

💡 利用シーン
  1. チャンクアップロードの整合性検証 (Tom が以前やった案件)
  2. ダウンロードしたファイルの改ざん検出 (公開ハッシュと比較)
  3. ローカルのバージョン管理: 内容が変わった時だけ保存
  チャンクアップロード文脈での使い方
  ┌─────────────────────────────────────┐
  │  巨大ファイル (100MB)               │
  │  → file.slice() で 1MB×100チャンク  │
  │  → 各チャンクの SHA-256 を計算      │
  │  → サーバへ {chunk, hash} 送信      │
  │  → サーバ再計算 → 一致なら受理       │

   string ──TextEncoder──▶ Uint8Array
