全体像 — Kiro / Q Developer とは何か

概要

AWSが提供するAIコーディング支援は大きく2系統。Amazon Q Developer=AWS運用に強い会話型アシスタント。Kiro=2025年11月GAの仕様駆動型 Agentic IDE。両者は競合ではなく役割分担の関係。

🔰 まずは1行で
Kiro = 「AI が IDE 全体で伴走する VS Code 派生」。
Q Developer = 「VS Code/JetBrains 拡張＋AWSコンソールに棲むチャット相棒」。 
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   [Kiro]                          [Amazon Q Developer]  │
│   ┌─────────────┐                 ┌─────────────┐       │
│   │  独立IDE    │                 │  拡張機能    │       │
│   │ (Code OSS)  │                 │ (VS Code等) │       │
│   └─────────────┘                 └─────────────┘       │
│         │                                │              │
│   仕様→設計→実装                AWS質問/コード補完     │
│   をエージェント主導            既存IDEに追加で導入     │
│                                                         │
│   ▼ 重い・本格開発              ▼ 軽い・既存IDE維持    │
│                                                         │
└─────────────────────────────────────────────────────────┘

# 製品の正体（公式情報ベース）
Kiro          : AWS発のAI IDE / Code OSS をフォーク
              : Specs / Hooks / Steering / Agent が中核
              : 2025-07 プレビュー → 2025-11 GA → 2026年も継続更新

Q Developer   : AWSの会話型AIアシスタント
              : VS Code, JetBrains, Visual Studio, Eclipse に拡張機能
              : AWSコンソール / CLI / Slack / Teams にも統合
              : Kiro CLI に CLI 機能は再ブランド統合中
観点KiroAmazon Q Developer
提供形態独立IDE (要インストール)拡張機能 + コンソール内蔵
得意領域仕様駆動の本格開発AWS環境のQ&A・補完・トラブル調査
料金Free / Pro / Pro+ (クレジット制)Free / Pro $19/月
VS Code資産設定/プラグインを引き継げるそのまま VS Code で使える
ターゲットプロト→本番に持ち上げたい人AWS運用者・既存VS Code利用者

Kiroインストール — 5分で起動まで

セットアップ

公式サイト kiro.dev からバイナリを落とすだけ。GA後はウェイトリスト不要。Windows/Mac/Linux 対応。 

# 手順 (Windows例)
1. https://kiro.dev/ にアクセス
2. [Download for Windows] ボタン押下
3. KiroSetup-x.x.x.exe を実行
4. インストールウィザードに従って進める
5. [Kiroを実行する] にチェックして完了

# 起動後の最初の画面で認証方法を選択
- Google
- GitHub
- AWS Builder ID    ← 個人検証ならこれが最速 (AWSアカウント不要)
- AWS Identity Center  ← 組織導入ならこちら
✗ Before（不要な手順を踏む）
Bash — 古い手順
# GA前 (2025年7-10月) の手順
1. ウェイトリスト登録
2. 招待メール待ち (数日〜数週間)
3. 招待後にダウンロード可能
✓ After（GA後 = 現在）
Bash — 現在の手順
# 2025年11月GA以降
1. kiro.dev で即ダウンロード
2. インストール → サインイン
3. 即利用開始 (待ち時間ゼロ)
⚠ WSL2 で起動エラーが出る場合: $PATH をシェルで明示設定する必要あり。Qiitaに「Kiro WSL2 起動」で具体的な手順あり。Cursor / Q CLI と相互干渉した時と同じパターン。
03

認証セットアップ — Builder ID と Identity Center

セットアップ

Kiro / Q Developer 共通の認証は2系統。個人検証は Builder ID、組織導入は Identity Center。混同すると料金や統制が破綻する。

項目AWS Builder IDIAM Identity Center (旧 SSO)
用途個人検証・学習組織展開・チーム利用
AWSアカウント不要必要
Free tier○○
Pro tier ($19/月)×○
SSO/SCIM×○
管理ダッシュボード×○
 
# Builder ID で始める最短手順
1. Kiro 起動 → [Sign in with AWS Builder ID]
2. ブラウザが自動で開く → メールアドレス入力
3. 確認コードがメールに届く → 入力
4. 完了。Free tier の月50クレジット + 初回ボーナス500クレジットが使える

# 確認コマンド (Kiro CLI を使う場合)
$ kiro-cli login
$ kiro-cli whoami    # 認証されているユーザを確認
📘 Free tier の中身 (2026年4月時点): 月50エージェントチャット / 1,000行のコード変換 / Builder ID で即利用可。Pro は $19/ユーザ/月で SOC2/IP補償/組織管理が付く。
⚠ データ取扱の差: Free tier の一部データはサービス改善に使われる場合あり、Pro tier は使われない。業務コードを扱うなら Pro 必須。
04

Vibeモード — 軽量プロトタイピング

Kiro機能

Kiro の2モードのうち軽い方。「こんな感じのもの作って」と話しかけるだけで動くものが出来る。Cursor や Claude Code と同じノリ。

🔰 Vibe Coding とは
AIに自然言語で指示してコードを生成する開発スタイル。「気分で作る」が語源。プロトタイプ・学習・趣味プロジェクトに最適。仕様書がないので大規模化すると破綻する。 
[ユーザ] ──「ToDoアプリ作って」──→ [Kiro Vibe]
                                       │
                                       ▼
                                  index.html
                                  app.js
                                  style.css
                                  ※仕様書なし

# Vibe モードの使い方 (Kiro IDE)
1. Kiro を起動 → 左側のチャットパネルを開く
2. プロンプト入力欄に自然言語で書く
   例: 「シンプルなToDoアプリをHTML/JS/CSSで作って」
3. [Send] → ファイルが順次生成される
4. 各ファイルの差分を [Accept] / [Reject] で確認
✓ 向いている用途: 動くものを15分で見せたい / 技術検証 / 個人ツール / 学習用サンプル
✗ 向いていない用途: 既存システム改修 / セキュリティ要件あり / 仕様書必須の業務開発 → 次の Spec モードへ
05

Specモード — 仕様駆動開発の核心

Kiro機能

Kiro の真骨頂。要件 → 設計 → タスク分解 → 実装の4段階を AI と人間で進める。各段階で人間が承認するので暴走しない。本番品質を狙う場合の標準ワークフロー。

🔰 Spec モードのフロー
[1] Requirements    [2] Design        [3] Tasks         [4] Implement
    要件定義     →    設計          →    タスク分解   →    実装
    requirements.md   design.md         tasks.md          各ファイル

  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ AIが起草  │    │ AIが設計  │    │ AIが分解 │    │ AIが実装  │
  └────┬─────┘    └────┬─────┘    └────┬─────┘    └────┬─────┘
       ▼               ▼               ▼               ▼
  人間が確認     人間が確認      人間が確認     人間が確認
  & 修正        & 修正         & 修正        & テスト
       │               │               │               │
       ▼               ▼               ▼               ▼
  [Move to       [Move to        [Finalize       [Done]
   Design]        Tasks]          tasks]

# 実例: イーサリアムウォレット作成

プロンプト: 「イーサリアムウォレットを作成したい」

[Step 1] requirements.md が自動生成される
   - ユースケース
   - 機能要件 (アドレス生成 / 送金 / 残高表示)
   - 非機能要件 (セキュリティ / パフォーマンス)
   ↓ 人間が読んで修正
   ↓ [Move to design phase]

[Step 2] design.md が自動生成される
   - アーキテクチャ図
   - データモデル
   - API設計
   ↓ [Generate task list]

[Step 3] tasks.md が自動生成される
   - [ ] T1: ethers.js セットアップ
   - [ ] T2: アドレス生成関数実装
   - [ ] T3: 送金関数実装
   - [ ] T4: UI コンポーネント
   ↓ [Finalize task list]

[Step 4] タスク順に実装が走る
   各タスク完了ごとに人間が Accept/Reject
✓ Spec モードのメリット: ① 要件が文書として残る ② 設計判断が追跡可能 ③ AIの暴走を各段階で止められる ④ 既存システム改修でも履歴を引き継げる
現在: After（Specモード）
✓ Spec: 要件→設計→タスク→実装
　半年後に他人が読んでも「なぜこの設計か」が分かる
　仕様書が残るので保守しやすい
✗ Vibe: 「いい感じに作って」だけ
　半年後の自分が「なぜこのコード？」となる
　仕様書なし → 改修時にAIに渡す情報がない

Steering — プロジェクトルールを永続化

Kiro機能

「毎回同じ指示を書かなくていい」仕組み。命名規則・コーディング規約・利用ライブラリを Markdown ファイルで Kiro に教え込む。React の CLAUDE.md や Cursor の .cursorrules 相当。 

# プロジェクトルートに配置
.kiro/
└── steering/
    ├── coding-style.md       # 命名規則
    ├── tech-stack.md         # 使う技術スタック
    └── do-not-touch.md       # 触ってはいけない場所

# coding-style.md の中身例
## TypeScript Style
- 関数は const + arrow で書く
- 変数名は camelCase, クラスは PascalCase
- any は禁止、unknown を使う

## ファイル構成
- components/ にUI、hooks/ にロジック
- 1ファイル1コンポーネント
📘 効果: Spec モードでもVibeモードでも、Kiro はこの steering ファイルを常に読み込んでコード生成する。チーム全員で共有すれば、AI生成コードのスタイルが統一される。
💡 Steering の典型的な使い方
  • 命名規則の統一: テーブル名は snake_case、変数名は camelCase など
  • 禁止事項の明示: 「var を使わない」「console.log は本番コードに残さない」
  • カスタムエージェント定義: 「AWS SAの分身」のような特定役割のAI
  • レビュー観点: 「セキュリティ・性能・可読性の順で確認」
07

Hooks — ファイル操作で自動実行

Kiro機能

ファイル保存・作成・削除をトリガに AI に作業させる仕組み。経験豊富な先輩が「あ、それ忘れてるよ」と気づくのを自動化したイメージ。

🔰 Hooks のメンタルモデル
[開発者の操作]            [Hook トリガ]          [AI の自動アクション]

ファイル保存 (Ctrl+S) ──→ "on save"        ──→ 関連ドキュメント更新
ファイル作成          ──→ "on create"      ──→ テストファイル雛形生成
コミット直前          ──→ "before commit"  ──→ 機密情報スキャン
手動ボタン            ──→ "manual trigger" ──→ READMEの目次再生成

# Hook の設定例 (Kiro IDE の AGENT HOOK 画面)

Hook Name: 機密情報スキャン
Trigger: ファイル保存時
Pattern: **/*.{js,ts,py}
Action: 「このファイルにAPIキー、パスワード、トークンが含まれていないか確認し、
        含まれていれば警告を出して .env への移動を提案して」

────

Hook Name: 関連テスト更新
Trigger: ファイル保存時
Pattern: src/components/*.tsx
Action: 「対応する __tests__ 配下のテストファイルを確認し、
        新しい関数や props があればテストケースを追加して」
✓ 嬉しいポイント: 自然言語で書ける。bash スクリプトや YAML を覚える必要がない。「やってほしいこと」を文章で書くだけ。
⚠ クレジットを消費する: Hook が走るたびに AI 呼び出しが発生 → クレジットを使う。Free tier の50クレジットだとすぐ枯渇する。重要な Hook だけ有効にするか、Pro 推奨。
08

Q Developer — VS Code 拡張で導入

Q Developer

普段の VS Code を変えずに AI 支援を足したいならこれが最速。拡張機能を入れて Builder ID でログインするだけ。 

# インストール手順 (VS Code)

1. VS Code を起動 → Extensions (Ctrl+Shift+X)
2. "Amazon Q" で検索 → [Install]
3. 左サイドバーに Amazon Q アイコンが出る → クリック
4. [Sign in with AWS Builder ID] を選択
5. ブラウザで認証 → コード入力 → 完了

# 主な使い方
- チャット     : 左パネルで自然言語で質問
- インライン補完 : コーディング中にゴーストテキストで提案
- /explain     : 選択コードを解説
- /fix         : バグ修正提案
- /test         : ユニットテスト生成
- /transform   : Java/.NETバージョンアップ
💡 Q Developer が真価を発揮するシーン
  • AWSサービス質問: 「S3 のCORS設定教えて」「Lambda の同時実行制限は？」
  • 既存コード調査: 開いたファイルを /explain で要約
  • セキュリティスキャン: 開いたコードに脆弱性がないか検査
  • レガシー変換: Java 8 → 17 / .NET Framework → .NET
  • AWSコンソールでの調査: コンソール上の Q アイコンで「実行中の EC2 を一覧」
こんなコード/状況を見たら使える候補:
  • 「このAWSエラー何だっけ…」 → コンソールの Q アイコンで質問
  • 200行のレガシー関数を読まされた → /explain で2分で把握
📘 料金感覚: Free tier は月50エージェントチャット + 1000行のコード変換。個人検証ならこれで足りる。チームで本格利用なら Pro $19/月。

業務での活用パターン — 既存IDE+業務コードへの組み込み

実践

OutSystems や Java 系の業務開発が中心の現場でも、「AI支援を足すだけ」の使い方なら段階的に導入できる。いきなり Spec モードに飛ばずに、Q Developer の補完から始めるのが現実的。

🔰 段階的導入の3ステップ
[Step 1] 個人で慣れる            (1-2週間)
   VS Code に Q Developer 拡張を入れる
   業務コードは触らず、技術調査やコード読解に使う
   ↓
[Step 2] 自分のサブタスクで試す  (1ヶ月)
   ユニットテスト生成、ドキュメント整理、ログ解析
   個人ツールやスクリプトを Kiro Vibe で作る
   ↓
[Step 3] チーム展開               (3ヶ月～)
   Pro 契約 + Identity Center で組織導入
   新規機能を Kiro Spec で起こす
   Steering ファイルでチーム規約を共有
業務シーン使うべきツール狙い
仕様書作成 (新規機能)Kiro Specrequirements.md → design.md を自動起草
既存コード読解Q Developer /explain200行の関数を3分で把握
ユニットテスト生成Q Developer /testカバレッジ底上げ
AWSリソース調査Q Developer (コンソール)「EC2 一覧」など即答
コーディング規約徹底Kiro SteeringAI生成コードのスタイル統一
定型作業の自動化Kiro Hooks保存時のドキュメント更新等
Java/.NET アップグレードQ Developer /transformレガシー一括変換
⚠ 業務導入の注意点: ① 機密コードを Free tier で扱わない (一部データがサービス改善に使われる) ② 生成コードは必ず人間レビュー (誤りや古い情報が混じる) ③ Preview機能を本番前提にしない (GitHub連携などはPreview段階)
✓ 最初の一歩のおすすめ: いまの VS Code に Q Developer 拡張を入れて、Builder ID で 1週間「コード読解だけ」に使ってみる。これだけで業務時間が体感で2割減る。慣れたら Kiro へ。
💡 OutSystems / 業務システム開発者向けの当てはめ
  • JS Extension の作成: Kiro Vibe で動くものを15分で → 既存パターンに合わせて手で整える
  • SQL クエリ最適化: Q Developer に EXPLAIN 結果を渡して改善案をもらう
  • レガシー Java バッチ調査: Q Developer /explain でロジック把握 → 仕様書化
  • 新規モジュール仕様策定: Kiro Spec で requirements.md を起草 → レビュー会で叩く
  • テストデータ生成: Vibe モードに「20件のサンプル顧客データをCSVで」
こんな状況なら導入を検討:
  • 同じような調査・コード読解を毎週繰り返している
  • 仕様書が口頭伝承化していて、新人が立ち上がるのに時間がかかる
  • レガシーコードの改修工数が見積もれない
