Web Worker — UIスレッドを止めない並列処理の入口

✓ iOS ✓ Android

Why exists: JavaScriptは元来シングルスレッド。重い計算をUIスレッドで回すと画面が固まり、Wijmo FlexGridのスクロールやボタン押下も全停止する。Web Workerは「別スレッドで動くJSサンドボックス」を postMessage 経由で扱える仕組みとして登場し、UI応答性を保護する第一の手段になった。

💡 利用シーン
  1. 大量データ(10万件)のクライアントサイド集計をWorkerに投げてグリッドの応答を保つ
  2. CSV/JSONのパース・バリデーションをUIから分離
  3. 暗号化・ハッシュ計算など長時間CPUを使う処理の隔離
  メインスレッド (UI)              Worker スレッド
  ─────────────────              ─────────────────
   ▼ ボタン押下
   worker.postMessage(data) ───▶ onmessage(data)
   ▼ (UIは止まらない)              ▼ 重い計算
   onmessage(result) ◀────────── postMessage(result)
   ▼ 画面更新

  ❌ Workerからは DOM/window/document へアクセス不可
  ✅ self / fetch / setTimeout / IndexedDB は使える
📌 OutSystems文脈での旨味: Wijmo FlexGridでitemsSourceに大量配列をセットする前段で、フィルタリングや集計をWorkerに投げると、グリッドのレンダリング前にUIフリーズが起きない。VB.NETサーバー側のバッチ処理でBackgroundWorkerクラスを使っていた感覚に近い ── が、Workerは 共有メモリではなく値コピー(structured clone) で渡る点が違う。OutSystems の OnReady 内で JavaScript ノードから new Worker() を起こしてもよいが、Worker用の.jsファイルをResourceとして配置する必要があるため、Lab 03のBlob URL方式が実用的。

function lab1Run() {
  const n = parseInt(document.getElementById('lab1-n').value, 10);
  const workerCode = `
    self.onmessage = (e) => {
      const fib = (k) => k < 2 ? k : fib(k-1) + fib(k-2);
      const t0 = Date.now();
      const result = fib(e.data);
      self.postMessage({ result, ms: Date.now() - t0 });
    };
  `;
  const blob = new Blob([workerCode], { type: 'application/javascript' });
  const worker = new Worker(URL.createObjectURL(blob));
  console.log('Worker起動 → fib(' + n + ')をpostMessage');
  const t0 = Date.now();
  worker.onmessage = (e) => {
    console.log('Worker結果: ' + e.data.result + ' (Worker側 ' + e.data.ms + 'ms)');
    setBA('lab1', 'UIフリーズなし', 'fib(' + n + ')=' + e.data.result + ' / 経過 ' + (Date.now()-t0) + 'ms');
    worker.terminate();
  };
  worker.postMessage(n);
}

Worker重い計算 — 素数列挙でUI応答性を実証

✓ iOS ✓ Android

Why care: 「Workerに投げれば速くなる」のではなく UIが止まらない ことに価値がある。同じ計算でも、UIスレッドで回すとカウンタが止まる/Workerなら回り続ける、を並べて見ると効果が直感できる。

💡 利用シーン
  1. クライアント側で大量レコードのフィルタリング・ソート
  2. 画像のピクセル単位処理(Lab 06のCanvas+Workerなど)
  3. 暗号化・電子署名の生成
  シナリオ: 1秒ごとに数を上げるカウンタ + 重い素数列挙
  ─────────────────────────────────────────────────
   同期実行    : ▓▓▓▓▓▓▓▓▓▓▓▓▓ (固まる)→計算終わるまでカウンタ停止
   Worker実行  : ▓░░░░░░░░░░ (UIは生きてる) カウンタ動き続ける

  → 体感速度の違いが出るのは「並列で他の処理が回せる」点
📌 OutSystems文脈での旨味: ScreenでTimer Action(クライアント)が動く中で重い計算を走らせると、Timerが遅延する。Workerに逃がすとTimerは止まらない。

JS — UIカウンタを動かしながらWorkerで素数列挙
function lab2Run() {
  const code = `
    self.onmessage = () => {
      const isPrime = (n) => {
        if (n < 2) return false;
        for (let i = 2; i * i <= n; i++) if (n % i === 0) return false;
        return true;
      };
      let count = 0;
      for (let i = 2; i <= 1000000; i++) if (isPrime(i)) count++;
      self.postMessage(count);
    };
  `;
  const w = new Worker(URL.createObjectURL(
    new Blob([code], { type: 'application/javascript' })));
  let tick = 0;
  const timer = setInterval(() => {
    tick++;
    setBA('lab2', 'UIカウンタ稼働中: ' + tick + ' tick', '(計算中…)');
  }, 100);
  const t0 = Date.now();
  w.onmessage = (e) => {
    clearInterval(timer);
    const ms = Date.now() - t0;
    console.log('素数の個数: ' + e.data + ' / Worker処理時間: ' + ms + 'ms');
    setBA('lab2', 'UIカウンタ ' + tick + ' 回稼働', '結果: ' + e.data + '個 / ' + ms + 'ms');
    w.terminate();
  };
  w.postMessage(null);
}

Service Worker基礎 — install / activate を Blob URL で登録

✓ iOS ✓ Android ⚠ HTTPS必須

Why this design: Service Workerは Web Worker と違い ページとは独立にバックグラウンドで生き続けるプロキシ。fetchを傍受してオフライン化できる代わり、登録・install・activate という独特なライフサイクルを持ち、なおかつ 別ファイルのJSとしてHTTPSで配信される必要がある。本ラボでは Blob URL で動的に SW スクリプトを生成して登録する手法を試す。

💡 利用シーン
  1. PWA化してホーム画面追加・オフライン動作対応
  2. プッシュ通知の受信エンドポイント
  3. 静的アセットの永続キャッシュ
  Service Worker ライフサイクル
  ─────────────────────────────────
   register(swUrl)
        │
        ▼
   ┌─────────┐    新バージョン検出時のみ
   │ install │ ─► (古いSWが残っていれば waiting 状態)
   └─────────┘
        │
        ▼
   ┌──────────┐
   │ activate │ ─► 古いSWを破棄、新SWが制御開始
   └──────────┘
        │
        ▼
   ┌────────────┐
   │ fetch傍受  │ ◄─ ページからのリクエストを代理
   └────────────┘

  ❌ Workerと違い "そのページが閉じても生き残る"
  ❌ HTTPS or localhost でしか動かない
📌 注意: navigator.serviceWorker.register() はSWスクリプトのURLを 同一オリジン で要求する。Blob URLは生成元オリジンを継承するためGitHub Pagesでもこの方式は通る。type: 'module' を付ければESM版SWも書ける。

async function lab3Run() {
  if (!('serviceWorker' in navigator)) {
    console.log('このブラウザはSW非対応');
    return;
  }
  const swCode = `
    self.addEventListener('install', (e) => {
      console.log('[SW] install');
      self.skipWaiting();
    });
    self.addEventListener('activate', (e) => {
      console.log('[SW] activate');
      e.waitUntil(self.clients.claim());
    });
  `;
  const url = URL.createObjectURL(
    new Blob([swCode], { type: 'application/javascript' }));
  try {
    const reg = await navigator.serviceWorker.register(url);
    console.log('登録成功 scope: ' + reg.scope);
    setBA('lab3', '未登録', 'SW active state: ' +
      (reg.active ? reg.active.state : reg.installing ? 'installing' : '?'));
  } catch (e) {
    console.log('登録失敗: ' + e.message);
    setBA('lab3', '未登録', 'エラー: ' + e.message);
  }
}

SW fetch傍受 — ネットワークの間に入って応答を作る

✓ iOS ✓ Android ⚠ HTTPS必須

Why this fails: Service Workerはあくまで「サーバとブラウザの間に挟まるプロキシ」。ファイル直開き(file://)では動かず、なおかつ register後すぐは fetch を傍受しない(activeになるまで)。本ラボでは「fetchイベントで合成レスポンスを返す」最小サンプルを試す。

💡 利用シーン
  1. オフライン時のフォールバックページ提供
  2. APIレスポンスの統一的なエラー変換
  3. テスト用にAPIをモック化
  fetch 傍受の流れ
  ────────────────────────────
   page → fetch('/api/foo')
            │
            ▼
        ┌─────────┐
        │   SW    │ ◄── fetchイベント発火
        │ fetch   │
        │ handler │
        └─────────┘
            │
       3つの選択肢:
       ① e.respondWith(new Response('合成')) ←作って返す
       ② e.respondWith(fetch(e.request))    ←そのまま通す
       ③ 何もしない                          ←ブラウザが普通にネット
📌 注意: 本ラボはSWが activate して clients.claim() を呼ぶまで fetch傍受は始まらない。実機でクリック後に /__sw_test__ をfetchして合成レスポンスが返るか確認する。

JS — fetchイベントで合成レスポンス
async function lab4Run() {
  const swCode = `
    self.addEventListener('install', () => self.skipWaiting());
    self.addEventListener('activate', (e) => e.waitUntil(self.clients.claim()));
    self.addEventListener('fetch', (e) => {
      const url = new URL(e.request.url);
      if (url.pathname.endsWith('/__sw_test__')) {
        e.respondWith(new Response(
          JSON.stringify({ from: 'service-worker', ts: Date.now() }),
          { headers: { 'Content-Type': 'application/json' } }
        ));
      }
    });
  `;
  const url = URL.createObjectURL(
    new Blob([swCode], { type: 'application/javascript' }));
  await navigator.serviceWorker.register(url);
  await navigator.serviceWorker.ready;
  console.log('SW ready, fetch試行中...');
  // SWが clients.claim() するまで待つ
  await new Promise(r => setTimeout(r, 500));
  try {
    const res = await fetch('/__sw_test__');
    const json = await res.json();
    console.log('合成レスポンス受信: ' + JSON.stringify(json));
    setBA('lab4', '通常fetchならネット経由', 'SWが合成: ' + JSON.stringify(json));
  } catch (e) {
    console.log('fetch失敗(SWまだactive前かも): ' + e.message);
    setBA('lab4', '?', 'エラー: ' + e.message + ' / 再度ボタン押下');
  }
}

Cache API — オフライン資源庫(SWなしでも動く)

✓ iOS ✓ Android ⚠ HTTPS必須

Why care: Cache APIは Request/Response ペアの 名前付き永続ストア。ServiceWorkerでオフライン化する際の必須路線だが、windowからも caches グローバルで触れる(SW登録不要)。Memory Cache, HTTP Cache, IndexedDB との立ち位置を整理しておく。

💡 利用シーン
  1. 静的アセット(CSS/JS/画像)の永続キャッシュ
  2. APIレスポンスのスナップショット保存(Stale-While-Revalidate)
  3. オフラインでも閲覧できるドキュメントの保持
  ストレージ比較
  ──────────────────────────────────────────
   名称         | 単位          | 永続性 | 容量目安
   ─────────────|───────────────|────────|─────────
   Memory Cache | URL→Response | タブ寿命| RAM依存
   HTTP Cache   | URL→Response | ブラウザ| 数百MB〜
   Cache API    | Req↔Res ペア  | 永続    | quotaに従う
   IndexedDB    | キー値オブジェクト| 永続  | quotaに従う
   localStorage | 文字列キー値   | 永続    | 5MB前後
📌 OutSystems文脈での旨味: モバイルアプリで「ネットワーク不安定でも前回の参照データを表示」というUX要件があるとき、APIレスポンスを Cache API に入れて Stale-While-Revalidate を組むと簡潔。

async function lab5Run() {
  if (!('caches' in window)) {
    console.log('Cache API非対応');
    return;
  }
  const cache = await caches.open('lab5-demo');
  const key = '/lab5-virtual';
  const value = { user: 'tom', cached_at: new Date().toISOString() };
  // put: Response を保存
  await cache.put(key,
    new Response(JSON.stringify(value),
      { headers: { 'Content-Type': 'application/json' } }));
  console.log('cache.put 完了 key=' + key);
  // match: 取り出し
  const cached = await cache.match(key);
  if (cached) {
    const json = await cached.json();
    console.log('cache.match 取得: ' + JSON.stringify(json));
    // 全キー一覧
    const keys = await cache.keys();
    console.log('cache内のkey数: ' + keys.length);
    setBA('lab5', '通常はAPIへ毎回HTTP', 'cache hit: ' + JSON.stringify(json));
  }
}

Geolocation — 位置情報の許可と取得

✓ iOS ✓ Android ⚠ HTTPS必須

Why this design: Geolocationは「ユーザ許可」と「衛星捕捉の遅延」と「拒否される可能性」が絡む。同期APIでは表現できないため、getCurrentPosition(success, error, options) というコールバック式と、現代では Promise でラップする使い方が定石。watchPosition で継続監視も可能だがバッテリ消費に注意。

💡 利用シーン
  1. 現場系業務アプリで作業地点の自動記録(訪問・点検・配送)
  2. 近くの店舗・営業所を距離順で表示
  3. 地図と組み合わせた現在地ピン表示(MapsTraditional)
  Geolocation 取得の3経路
  ───────────────────────────────────────
   ┌──────────────────────────────┐
   │ navigator.geolocation         │
   │   .getCurrentPosition(...)    │
   └──────────┬───────────────────┘
              │
        ┌─────▼─────┐
        │ 許可済み? │
        └─┬───────┬─┘
       Yes│       │No → 初回のみ許可ダイアログ
          │       └────────────────────┐
          ▼                            ▼
   位置取得 (GPS or WiFi or IP)    Yes:取得 / No:errorコールバック
       (10-30秒かかる場合あり)         code=1 (PERMISSION_DENIED)
          │
          ▼
    success({coords: {lat, lng, accuracy}, timestamp})

  options:
    enableHighAccuracy: true  → GPSを使う(屋外向け、遅い)
    timeout: 10000            → 10秒で諦める
    maximumAge: 60000         → 60秒以内のキャッシュ位置を許容
📌 OutSystems文脈での旨味: Mobile Appで「現場に到着したら自動的に出勤打刻」のような要件は、OutSystemsのLocationプラグイン(Cordova/Capacitor)経由でも、Webブラウザ向けScreenでも標準のGeolocation APIで実装できる。
OutSystemsのClient ActionからJavaScriptノードでこのAPIを呼び、結果をLocal EntityにInsertOrUpdateする流れが定番。注意: watchPositionを仕込んだままScreenを離れるとIDが残るので、OnDestroy相当のタイミングで clearWatch(id) する。Wijmo FlexGridで「現在地から近い順に並べ替え」を実装する際は、Geolocation取得後に CollectionView.sortDescriptions を再構築するパターンが扱いやすい。

function lab6Run() {
  if (!navigator.geolocation) {
    console.log('Geolocation非対応');
    return;
  }
  console.log('位置情報取得中…(初回は許可ダイアログ)');
  const opts = { enableHighAccuracy: false, timeout: 10000, maximumAge: 60000 };
  const promisify = () => new Promise((resolve, reject) =>
    navigator.geolocation.getCurrentPosition(resolve, reject, opts));
  promisify().then(pos => {
    const c = pos.coords;
    console.log('lat=' + c.latitude.toFixed(5) + ' lng=' + c.longitude.toFixed(5));
    console.log('精度=' + Math.round(c.accuracy) + 'm');
    setBA('lab6', '位置不明', '緯度: ' + c.latitude.toFixed(5)
      + ' / 経度: ' + c.longitude.toFixed(5) + ' / 精度: ' + Math.round(c.accuracy) + 'm');
  }).catch(err => {
    const codes = ['', 'PERMISSION_DENIED', 'POSITION_UNAVAILABLE', 'TIMEOUT'];
    console.log('エラー code=' + err.code + ' (' + codes[err.code] + ')');
    setBA('lab6', '位置不明', 'エラー: ' + (codes[err.code] || err.message));
  });
}

DeviceOrientation — 端末の傾き(iOSは許可必須)

✓ iOS 13+ ✓ Android ⚠ HTTPS必須

Why this fails: 「Androidでは動くのにiPhoneで動かない」と詰むAPIの代表。iOS 13+ では DeviceOrientationEvent.requestPermission() をユーザジェスチャ(クリック等)起点で呼ばないとイベントが流れない。さらに座標系も alpha(コンパス基準/絶対方位)が iOS と Android で扱いが微妙に違うため、傾き検知に使うなら beta/gamma を中心に設計する。

💡 利用シーン
  1. 水準器・傾き計測アプリ
  2. ARっぽい視点切替(端末を傾けると画面が回る)
  3. 傾けて操作するゲーム的UI
  DeviceOrientation の3角度
  ───────────────────────────────
       z (alpha)
        ▲
        │      x (gamma)
        │     ╱
        │    ╱
        ●───────► y (beta)

   alpha: 0..360 (コンパス方位、Z軸まわり)
   beta : -180..180 (前後の傾き、X軸まわり)
   gamma: -90..90 (左右の傾き、Y軸まわり)

  iOSの初手シーケンス:
   ① ユーザボタンクリック
   ② DeviceOrientationEvent.requestPermission() を呼ぶ
   ③ "granted" が返ってきたら addEventListener する
📌 2段階UI必須: iOSでは「許可リクエスト」「開始」を別ボタンに分けるのが安全。許可が取れていても、ページ読込み直後にいきなり addEventListener するとイベントが流れない。

DeviceMotion — 加速度センサー(振動検知)

✓ iOS 13+ ✓ Android ⚠ HTTPS必須

Why care: 加速度から「歩いた」「振った」「落下した」を検知できる。Lab 07 と同じく iOS では DeviceMotionEvent.requestPermission() が必要。本ラボでは「シェイク」を簡易的に検知する。

💡 利用シーン
  1. シェイクで取消・アンドゥ(モバイルアプリで定番)
  2. 歩数計・万歩計
  3. 落下検知(端末を落としたら警告音)
  DeviceMotion の主なフィールド
  ───────────────────────────────
   acceleration             : 重力を除いた加速度 {x,y,z} m/s²
   accelerationIncludingGravity : 重力込み {x,y,z}
