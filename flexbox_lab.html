00

なぜFlexboxが生まれたか

基本

Flexbox前のCSSは「文書」を流すモデル。float や table では 垂直中央・等高カラム・余白配分 の3つが激しく苦しかった。その正体は「1本の軸に沿って箱と余白をどう配るか」という共通問題。

🔰 一番大事な発想の転換
Flexbox の核心は 「余白(free space)を能動的に配る道具」。
迷ったら必ずこの一文に戻る → 「これは余白を、どの軸に、どう配る指示か?」 
通常フロー : 内容のサイズ → 箱が決まる（余白は受動的に「余ったもの」）
Flexbox   : コンテナのサイズ → 中身を伸縮させ配る（余白は能動的に「配るもの」）
                                        ↑ Δ(価値) = 余白を第一級の操作対象にした

Before：float で横並び（苦しみの例）

✗ Before（float 時代）
/* 横並びの度に float + clearfix が必須 */
.col { float:left; width:33.33%; }
.row::after { content:""; display:block; clear:both; }
/* 等高にも垂直中央にもならない… */
✓ After（Flexbox）
/* 1宣言で横並び・等高・中央すべて解決 */
.row { display:flex; gap:12px; align-items:center; }
.col { flex:1; }

display:flex とフォーマッティングコンテキスト

基本

display:flex（または inline-flex）は Flexフォーマッティングコンテキスト(FFC) を生成するスイッチ。ここで通常フローのルールが停止し、Flexのルールに切り替わる。直接の子だけがFlex Itemになる（孫は無関係）。

.container { display:flex; }       /* 親=blockのように振る舞う */
.container-inline { display:inline-flex; } /* 親=inlineのように振る舞う */

02

主軸 / 交差軸という抽象

基本

Flexboxは「左右上下」で考えない。主軸(main axis) と 交差軸(cross axis) で考える。flex-direction を変えると、この軸が丸ごと回転し、全配分プロパティの基準が入れ替わる。

🔰 なぜ「幅・高さ」を捨てたか
具体語(幅/高さ)で定義すると column にした瞬間に意味が破綻する。axis という抽象を1枚かませることで、1セットのプロパティが row でも column でも(RTLでも)同じ意味を保てる。 
row :  main-start ──► main axis ──► main-end   （主軸=横）
column:        main-start
                  │  main axis（主軸=縦）
                  ▼  main-end
役割固定: justify-content = 主軸方向 / align-items = 交差軸方向

1
2
3
現在: flex-direction: row（主軸=横）
⚠ -reverse は視覚順だけを逆転させる。DOM順・Tab順・読み上げ順は変わらないため、アクセシビリティ注意。

06

gap と margin の違い

基本

gap はitem間にだけ溝を入れ、端には付かない。margin の「端にも付く／最後の要素で除外が面倒」という副作用を解消する。

✗ Before（margin で隙間）
.item { margin-right:12px; }
/* 最後の要素の余分な右余白を */
.item:last-child { margin-right:0; }
/* …という除外が常に必要 */
✓ After（gap）
.container { display:flex; gap:12px; }
/* 端には付かない。除外コード不要 */
/* row-gap / column-gap で個別指定も可 */

3
現在: gap: 8px（item間のみ。両端は密着）
07

flex-basis と width

中級

flex-basis は 主軸方向の初期サイズ（配分計算の出発点）。width は「左右の絶対サイズ」だが basis は「軸に追従する width」。主軸方向では basis が width に優先する。

🔰 配分計算は3ステップ
Step1  各itemの flex-basis を初期占有サイズとして置く
Step2  basisの合計 と コンテナのmainサイズ を比較
Step3  余る → grow で配る ／ 足りない → shrink で削る
basis:auto = 自分のwidth/内容を初期値に使う ／ basis:0 = 初期ゼロでgrow比率だけでサイズ決定。

basis可変

現在: 2個目 flex-basis: auto（内容サイズが初期値）
⚠ 主軸が縦(column)のとき width は無関係になり、flex-basis が「高さ」を意味する。だから両方存在する。

flex-grow（余りの山分け＝比率）

中級

余白が正のとき、それを何対何で取り合うかの重み（比率）。絶対pxでなく比率だから、コンテナ幅が変わっても意図(例:2倍幅)が保たれる。

/* 幅600・basis:0・grow 1,1,2 → 150 : 150 : 300 */
// item1 = 600×(1/4)=150,  item3 = 600×(2/4)=300
シナリオ:
短
中くらいの文
とても長いテキストの項目です
現在: flex:1 1 0 ×3 → 内容を無視した完全な3等分
📘 flex:1(basis=0)は内容無視で等分、flex:auto(basis=auto)は内容差を残して余白を分配。ボタンで比べると一目瞭然。
09

flex-shrink（不足の削減＝basis加重）

上級

余白が負（はみ出す）とき、どの割合で縮むかの重み。growと違い basis のサイズで重み付けされる＝大きい箱ほど多く縮む。

🔰 なぜ grow と非対称なのか
大きい箱ほど「縮ませる余地」が大きいから。小箱と大箱を同率で縮めると小箱が先に潰れて不自然。 
伸ばす時(grow) : 公平に（単純比率）
縮める時(shrink): 体格に応じて（basis加重比率）
実際の縮小量 = shrink値 × その item の basis  の比で配分
シナリオ（コンテナ幅 360px に制限）:
100
200
300
現在: shrink全=1 → basis加重で大きい箱ほど多く縮む（約60/120/180px）
⚠ 「全 shrink:0」を選ぶと誰も縮まず合計600pxが360pxの枠を溢れ、デモ枠にスクロールバーが出る（=overflow）。

min-width:auto の罠（最頻トラブル）

上級

flex-shrink:1 なのに子が縮まずコンテナを突き破る現象。原因はFlex Itemの min-width 初期値が auto（=コンテンツ最小サイズが下限） だから。

テキスト項目の min-width:
固定90px
これはとても長いテキストで枠を突き破ろうとします
現在: min-width: auto（最長語が下限になり縮まずはみ出す）
/* 解決: はみ出させたい item に下限を解除 */
.item { min-width:0; }       /* column方向なら min-height:0 */
/* + overflow:hidden / text-overflow:ellipsis で「…」省略 */
📘 なぜ既定がautoか＝文字が読めなくなるほど潰れる事故を防ぐ安全弁。省略やスクロールをしたい時だけ min-width:0 で解除する。
13

Flexbox vs Grid 使い分け

中級

判断の一言：1方向に流したい→Flex／縦横を同時に格子状に揃えたい→Grid。両者は対立せず、Gridのセル内をFlexで整える入れ子が王道。

Flexbox（1次元）Grid（2次元）
得意1本の軸に並べる行と列を同時に揃える
発想content-out寄り（中身で伸縮）container-in（先に枠を切る）
最適例ナビ/ツールバー/ボタン列/タグ群ページ骨格/カード格子/表組み
▶ Flex が向く場面
/* 中身次第で可変な横並び */
.toolbar { display:flex; gap:8px;
  align-items:center; }
▶ Grid が向く場面
/* 行も列もピシッと揃える格子 */
.cards { display:grid;
  grid-template-columns:repeat(3,1fr); gap:16px; }
✓ 迷ったら全Labで使った問い 「余白を、どの軸に、どう配るか」 に戻る。1軸ならFlex、2軸が必要になったらGrid。
