01

fetch — HTTPリクエストの標準API

✓ iOS ✓ Android

XMLHttpRequest の現代版。Promiseベースで、GET/POST/JSON/FormDataを統一的に扱える。OutSystems のCSAやReactフロントから REST APIを叩くときの土台。

💡 利用シーン
  1. OutSystems Server Action を REST 公開して CSA から呼ぶ
  2. 外部APIから JSON 取得して Wijmo FlexGrid に流し込む
  3. POST で SubmitOrder API を呼び、結果で画面遷移
  fetch(url, options)
    │
    ├─ Promise<Response> を返す
    │   │
    │   ├─ res.ok          (status 200-299 で true)
    │   ├─ res.status      (200, 404, 500 など)
    │   ├─ res.json()      → Promise<Object> (Body を消費)
    │   ├─ res.text()      → Promise<string>
    │   └─ res.blob()      → Promise<Blob>
    │
    └─ ⚠ Body は1回しか読めない (ストリーム)
📌 OutSystems文脈での旨味: Server Action を REST化して fetch で叩けば、CSA(Client-Side Action)外でも同じAPIを再利用可。Token はヘッダで送る。

}

Headers / Request / Response — fetch の構成要素

✓ iOS ✓ Android

fetch の引数と戻り値の正体。Headers は Map ライク、Request/Response は再利用や clone が可能なオブジェクト。Service Worker でも頻出。

💡 利用シーン
  1. Authorization ヘッダに Bearer Token を載せて API を叩く
  2. Response を clone() してログとUIで2回 body を読む
  3. Request オブジェクトを使い回して同じリクエストを複数発射
  Request                       Response
  ┌──────────────┐              ┌──────────────┐
  │ url          │              │ status       │ 200/404/500
  │ method       │  fetch(req)  │ statusText   │ "OK"
  │ headers ─────┼─────────────►│ headers ─────┤ Map-like
  │ body         │              │ body (Stream)│
  │ mode/cred.   │              │ ok / type    │
  └──────────────┘              │ clone()      │ ⭐ 2回読める
                                └──────────────┘
⚠ body の二度読み禁止: res.json() 後にもう一度 res.text() はできない。両方欲しいなら res.clone() してから片方を読む。

function lab2Headers() {
  const h = new Headers();
  h.append('Authorization', 'Bearer xxx.yyy.zzz');
  h.append('X-Trace-Id', 'abc-123');
  h.set('Content-Type', 'application/json');

  console.log(`get X-Trace-Id: ${h.get('X-Trace-Id')}`);
  // Headers は反復可能
  for (const [k, v] of h.entries()) {

  });

}

FormData — フォーム送信 / multipart 構築

✓ iOS ✓ Android

multipart/form-data を簡単に組み立てる。ファイルアップロードは fetch の body に渡すだけで Content-Type も自動付与される。

💡 利用シーン
  1. OutSystems で画像/CSVを REST API へアップロード
  2. HTML form の値をまとめて API に POST
  3. 動的にフィールドを追加して送信(タグ複数選択など)
  HTML <form>            FormData (JS)
  ┌────────────┐         ┌──────────────────┐
  │ name=foo   │         │ append('name','foo')
  │ file=img   │ ───────►│ append('file', File)
  └────────────┘         └────────┬─────────┘
                                  │
                                  ▼
                         multipart/form-data 自動構築
                         (Content-Type 境界文字列含む)
                                  │
                                  ▼
                         fetch(url, { method:'POST', body: fd })
📌 注意: FormData を body に渡すとき Content-Type ヘッダは 手動で設定しない。boundary が壊れる。fetch が自動で正しい multipart ヘッダを付ける。

AbortController + fetch — リクエストのキャンセル / タイムアウト

✓ iOS ✓ Android

fetch に signal を渡し、外から abort() で中断する。タイムアウト・ユーザのキャンセル操作・遷移時のクリーンアップに必須。File 03 のイベント編にも登場した汎用機構。

💡 利用シーン
  1. 5秒以内に応答が無ければ自動キャンセル(タイムアウト)
  2. ユーザが画面を切り替えたら未完了fetchを中断(リーク防止)
  3. 連打されたら前のリクエストを破棄して最新だけ採用
  ┌─────────────────────────────────────────────────┐
  │  const ctrl = new AbortController()            │
  │                                                 │
  │  fetch(url, { signal: ctrl.signal })           │
  │       │                                         │
  │       │   ◄────── ctrl.abort()                 │
  │       │           (タイムアウト or ユーザ操作)│
  │       ▼                                         │
  │  Promise reject → AbortError                   │
  └─────────────────────────────────────────────────┘
📌 OutSystems文脈での旨味: BPT で長時間かかるサーバ処理を呼ぶときに 30秒タイムアウトを設定したい場合、CSA で AbortController + setTimeout で組める。

// 2秒で自動タイムアウト (httpbin /delay/5 は5秒返さない)
async function lab4Timeout() {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), 2000);
  console.log('fetch開始 (delay=5s, timeout=2s)');
  try {
    const res = await fetch('https://httpbin.org/delay/5',
                            { signal: ctrl.signal });
    console.log(`まさかの成功: ${res.status}`);
  } catch (e) {
    console.log(`例外: ${e.name} - ${e.message}`);
  } finally {
    clearTimeout(timer);
  }
}

URL / URLSearchParams — URLの組み立てとクエリ操作

✓ iOS ✓ Android

文字列連結でURLを作るな、の答え。エンコード/デコードを正しく扱い、クエリパラメータを Map ライクに編集できる。

💡 利用シーン
  1. 検索画面の絞り込み条件をクエリ文字列にまとめて API へ
  2. OutSystems URL から token=xxx を解析してログイン状態判定
  3. 絶対/相対URL の解決 (base + path)
  URL コンストラクタ
  ┌───────────────────────────────────────────────────┐
  │ const u = new URL('/api?q=foo', 'https://ex.com')│
  │                                                   │
  │ u.protocol  → "https:"                           │
  │ u.host      → "ex.com"                           │
  │ u.pathname  → "/api"                             │
  │ u.search    → "?q=foo"                           │
  │ u.searchParams (URLSearchParams)                 │

localStorage — オリジン単位の永続キー値ストア

✓ iOS ✓ Android ⚠ Sandbox不可

同じオリジンで永続化されるキー値ストア(タブを閉じても残る)。値は文字列のみ。容量目安は5-10MB。同期APIなのでメインスレッドをブロックする点に注意。

💡 利用シーン
  1. OutSystemsで User Token / 表示設定を保存し、リロード後も維持
  2. 下書きフォームの内容を localStorage に退避(誤閉じ対策)
  3. ダークモード/言語設定など UI Preference の永続化
  オリジン (https://example.com) ────────────┐
  ┌─────────────────────────────────────────┐│
  │ localStorage                            ││ ← タブを閉じても消えない
  │  ├─ "user.token"  → "abc.def.ghi"      ││
  │  ├─ "ui.theme"    → "dark"             ││
  │  └─ "form.draft"  → '{"title":"..."}' ││
  ├─────────────────────────────────────────┤│
  │ sessionStorage  ※タブ単位/閉じたら消える││
  └─────────────────────────────────────────┘│
                                              ▼
  別オリジン (https://other.com) は別の領域  ← 隔離
⚠ 同期API: 大量書込はメインスレッド停止の原因に。1キー数十KB以上を頻繁に書くなら IndexedDB を検討。値はオブジェクトを JSON.stringify してから保存する。

sessionStorage — タブ単位で生きるキー値ストア

✓ iOS ✓ Android ⚠ Sandbox不可

localStorageと API は同じだが、寿命が「タブを閉じるまで」。リロードでは残るが、新規タブには引き継がれない。一時的な状態保持に。

💡 利用シーン
  1. 多段ウィザードの途中状態をリロード復帰用に保持
  2. ログイン後の一時トークンをタブ閉じで自動破棄
  3. OAuth state パラメータの突合確認用
  比較表
  ┌──────────────────┬───────────────┬──────────────┐
  │ 観点             │ localStorage  │ sessionStorage│
  ├──────────────────┼───────────────┼──────────────┤
  │ 寿命             │ 永続           │ タブ閉じまで  │
  │ 別タブと共有     │ ◯ 同オリジン   │ ✗ 隔離       │
  │ リロード後       │ 残る           │ 残る          │
  │ 容量目安         │ 5-10MB        │ 5-10MB       │
  │ API              │ 同じ           │ 同じ          │
  └──────────────────┴───────────────┴──────────────┘
📌 使い分け: 「次回もユーザに見せたい」→ localStorage。「このタブを閉じたら忘れたい」→ sessionStorage。OAuth の state は後者が安全。

document.cookie — 文字列ベースのCookie操作

✓ iOS ✓ Android ⚠ HttpOnly不可視

JSから読み書きできるCookie。HttpOnly属性のCookieは見えない(認証用は通常HttpOnly)。新APIの CookieStore は iOS Safari 未対応のため document.cookie が現実解。

💡 利用シーン
  1. OutSystems osVisitorCookie の確認・読み取り
  2. CSRF対策トークンを Cookie ↔ ヘッダで突合
  3. UIプリファレンス(言語/テーマ)を Cookie でサーバへ自動送信
  document.cookie の癖
  ┌─────────────────────────────────────────────────┐
  │ 読み: 全Cookieが "k1=v1; k2=v2; k3=v3" の文字列 │
  │       → split で自分でパースする必要あり        │
  │                                                 │
  │ 書き: cookie = "k=v; path=/; max-age=3600"     │
  │       → 1個ずつ書く (上書きではなく追加)        │
  │                                                 │
  │ 属性                                            │
  │  ├─ path=/         全パスに送信                 │
  │  ├─ max-age=N      N秒後に失効                  │
  │  ├─ Secure         HTTPSのみ送信                │
  │  ├─ SameSite=Lax   クロスサイト保護             │
  │  └─ HttpOnly ※    JSから不可視 (サーバ側設定)  │
  └─────────────────────────────────────────────────┘
⚠ HttpOnly: サーバが Set-Cookie: ...; HttpOnly で送ると JS から一切見えない。認証Cookieはこれが基本。XSSで盗まれるのを防ぐため。

function lab8Parse() {
  // "k1=v1; k2=v2" を Map にパース
  const map = new Map(
    document.cookie.split('; ')
      .filter(s => s)

  for (const [k, v] of map) {
    console.log(`  ${k} = ${v.slice(0, 30)}`);

navigator.storage.estimate — 使用容量と上限の取得

✓ iOS ✓ Android

オリジンが使えるストレージの上限と現在使用量を取得。IndexedDB / Cache / localStorage の合計値。容量警告UIや事前判定に使う。

💡 利用シーン
  1. 大きな添付ファイルを保存する前に空き容量チェック
  2. オフライン用キャッシュが上限の8割を超えたら古いものを削除
  3. ユーザに「現在 12MB / 1GB 使用中」と表示
  navigator.storage.estimate()
       │
       ▼
   { quota: 1073741824,    // バイト (上限の目安)
     usage: 12582912,      // バイト (使用中)
     usageDetails: {        // ※ ブラウザ依存
       indexedDB: 8000000,
       caches:     3000000,
       ...
     } }

  使用率 = usage / quota
📌 注意: 値は環境依存。iOS Safari は控えめ(数十MB〜)、Chrome Android は GB 級。あくまで「これ以上使ったら追い出される可能性がある」目安。

async function lab9Estimate() {
  if (!navigator.storage?.estimate) {
    console.log('未対応のブラウザです');
    return;
  }
  const e = await navigator.storage.estimate();
  const mb = (n) => (n / 1024 / 1024).toFixed(2) + ' MB';
  console.log(`使用中:  ${mb(e.usage)}`);
  console.log(`上限:    ${mb(e.quota)}`);
  console.log(`使用率:  ${(e.usage / e.quota * 100).toFixed(2)}%`);
  if (e.usageDetails) {
    for (const [k, v] of Object.entries(e.usageDetails)) {
      console.log(`  ${k}: ${mb(v)}`);
    }
  }
}

async function lab9Persist() {
  if (!navigator.storage?.persisted) {
    console.log('未対応');

// 多段イベントAPIをPromiseで包む薄いヘルパ
function idbOpen(name, version, onUpgrade) {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open(name, version);
    req.onupgradeneeded = (e) => onUpgrade(req.result, e.oldVersion);
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });
}
function idbReq(req) {
  return new Promise((resolve, reject) => {
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });
}

async function lab12Cursor() {
  const db = await idbOpen('lab4_db', 1, () => {});
  const store = db.transaction(['items'], 'readonly').objectStore('items');
  let count = 0;
  await new Promise((resolve, reject) => {
    const req = store.openCursor();
    req.onsuccess = (e) => {
      const cur = e.target.result;
      if (!cur) { resolve(); return; }
      count++;
