SOAPとは何か（Envelopeの全体像）

基本

SOAP は XML メッセージを必ず Envelope（封筒）に包んで HTTP の上で送受信するメッセージング仕様。 REST が URL + JSON で表すのに対し、SOAP は「決まった形の封筒」を往復させる。まずは送信する1通の全体像を見る。

SOAP リクエスト例 — Add(3,4)
<?xml version="1.0" encoding="utf-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/"
               xmlns:tns="http://example.com/calculator">
  <soap:Body>
    <tns:Add>
      <tns:a>3</tns:a>
      <tns:b>4</tns:b>
    </tns:Add>
  </soap:Body>
</soap:Envelope>
🔰 封筒のイメージ
SOAP は「中身（用件）を、決まった形の封筒に必ず入れる」ルール。封筒の外側＝HTTP、中身＝XML。 
┌─ soap:Envelope ────────────┐  ← 封筒（必須・ルート）
│  ┌─ soap:Header (任意) ──┐  │  ← 付箋（認証など）
│  └───────────────────────┘  │
│  ┌─ soap:Body (必須) ────┐  │  ← 便箋（本文＝用件）
│  │   tns:Add { a, b }    │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
01

Envelope / Header / Body の文法

基本

Envelope 直下に書けるのは Header（任意）と Body（必須）だけ。順序も決まっている。 Header には認証やトランザクションなどの「メタ情報」、Body には実データ（操作と引数）を入れる。

要素必須?個数役割
Envelope必須1（ルート）メッセージ全体の封筒
Header任意0 か 1認証 / WS-Security 等のメタ情報
Body必須1操作＋引数、または Fault
Header 付きの例（認証トークンを添える）
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Header>
    <auth:Token xmlns:auth="http://example.com/auth">abc123</auth:Token>
  </soap:Header>
  <soap:Body> <!-- 本文 --> </soap:Body>
</soap:Envelope>
02

アプリ起動と最初の送受信(Add)

基本

自作アプリ server.js を起動し、組み込みの計算機サービスへ Add(3,4) を送って 7 が返ることを確認する。 UI（ブラウザ）でも curl（端末）でも同じサービスを叩ける。

① サーバー起動（PowerShell）
cd C:\Users\user\ClaudeCode\SOAP
node server.js
# → UI : http://127.0.0.1:8088/ が表示されれば起動成功
② curl で Add を送信（別の端末）
curl -s -X POST http://127.0.0.1:8088/soap -H "Content-Type: text/xml" ^
  -d "<soap:Envelope xmlns:soap='http://schemas.xmlsoap.org/soap/envelope/' xmlns:tns='http://example.com/calculator'><soap:Body><tns:Add><tns:a>3</tns:a><tns:b>4</tns:b></tns:Add></soap:Body></soap:Envelope>"
# → <tns:AddResult>7</tns:AddResult> が返れば成功
03

SOAPAction ヘッダー

中級

SOAPAction は XML の中ではなく外側の HTTP ヘッダー。本文を解析せずに「リクエストの意図」を伝えるためのもの。 SOAP 1.1 では値をダブルクォートで囲む。WSDL の soap:operation に定義された値を使う。

HTTP リクエスト全体（ヘッダーと本文の位置関係）
POST /soap HTTP/1.1
Host: 127.0.0.1:8088
Content-Type: text/xml; charset=utf-8
SOAPAction: "http://example.com/calculator/Add"   ← ★ HTTP層。XML本文の外
Content-Length: 312

<?xml version="1.0"?>           ┐ ここからが本文（HTTPボディ）
<soap:Envelope ...>...            ┘
項目SOAP 1.1SOAP 1.2
SOAPAction独立した HTTP ヘッダー廃止 → Content-Type の param へ
書き方SOAPAction: "...../Add"Content-Type: ...; action="...../Add"
クォートダブルクォート必須action="" の中に記述
04

SOAP Fault（異常応答）

中級

SOAP ではエラーも正常な SOAP メッセージとして Body 内の Fault で返すのが作法。 アプリで Divide(20,0) を送ると、ゼロ除算で Fault が返る。

ゼロ除算で返る Fault（HTTP 500）
<soap:Fault>
  <faultcode>soap:Server</faultcode>       <!-- 機械可読 -->
  <faultstring>ゼロ除算はできません。</faultstring> <!-- 人間可読 -->
</soap:Fault>
faultcode意味責任の所在
soap:Clientリクエストが不正（引数不足など）送信側（送り直しても同じ）
soap:Server処理側の問題（ゼロ除算など）サーバー側（後で成功し得る）
curl で Fault を発生させる
curl -s -X POST http://127.0.0.1:8088/soap -H "Content-Type: text/xml" ^
  -d "<soap:Envelope xmlns:soap='http://schemas.xmlsoap.org/soap/envelope/' xmlns:tns='http://example.com/calculator'><soap:Body><tns:Divide><tns:a>20</tns:a><tns:b>0</tns:b></tns:Divide></soap:Body></soap:Envelope>"

WSDL の構造と読み方

中級

WSDL は「サービスの取扱説明書」。何ができ / 型は何か / どこに送るかを機械可読で記述する。 SOAP は封筒の形しか決めないため、使い方を伝える WSDL が必要になる。読むときは下から上が分かりやすい。

🔰 WSDL の5部品（抽象 → 具象）
definitions
 ├─ types     … 型(XML Schema)        [抽象]┐ 何を
 ├─ message   … 入出力メッセージ       [抽象]┤
 ├─ portType  … 操作一覧(in/out)      [抽象]┘ できる?
 ├─ binding   … 運び方(SOAP/HTTP)     [具象] どう運ぶ?
 └─ service   … 送り先URL(location)   [具象] どこへ?

読む順 = 下から: service→binding→portType→message/types
WSDL 抜粋 — binding の soapAction と service の URL
<binding name="CalculatorBinding" type="tns:CalculatorPortType">
  <soap:operation soapAction="http://example.com/calculator/Add"/>
</binding>
<service name="CalculatorService">
  <port ...><soap:address location="http://127.0.0.1:8088/soap"/></port>
</service>

SOAP 1.1 vs 1.2

中級

SOAP には 1.1（事実上の業界標準・本アプリ採用）と 1.2 がある。名前空間 URI で版が決まるのが要点。 SOAPAction の扱いと Content-Type が大きく異なる。

観点SOAP 1.1SOAP 1.2
Envelope NSschemas.xmlsoap.org/soap/envelope/www.w3.org/2003/05/soap-envelope
SOAPAction独立 HTTP ヘッダーContent-Type の action param
Content-Typetext/xmlapplication/soap+xml
Fault 構造faultcode / faultstringCode/Value, Reason/Text
SOAP 1.1 — 独立ヘッダー方式
HTTP ヘッダー
Content-Type: text/xml; charset=utf-8
SOAPAction: "http://example.com/calculator/Add"
SOAP 1.2 — Content-Type 統合方式
HTTP ヘッダー
Content-Type: application/soap+xml; charset=utf-8;
  action="http://example.com/calculator/Add"

プロキシと CORS 回避

応用

ブラウザは別オリジンへ直接 SOAP を送ると CORS で応答を読めず失敗しがち。 そこで同一オリジンの /proxy に依頼し、サーバーが代理で外部へ送って結果を返す。

🔰 なぜ間にサーバーを挟むのか
[直接] ブラウザ ──X──> 外部SOAP   ← 別オリジン=CORSで読めない
[経由] ブラウザ ──JSON──> /proxy ──SOAP──> 外部SOAP
                          (同一オリジン)  (サーバ間=CORS制約なし)
        ブラウザ <──JSON── /proxy <──応答──┘
/proxy への依頼（JSONで包む）
curl -s -X POST http://127.0.0.1:8088/proxy -H "Content-Type: application/json" ^
  -d "{\"url\":\"http://127.0.0.1:8088/soap\",\"soapAction\":\"http://example.com/calculator/Multiply\",\"body\":\"<soap:Envelope ...>...</soap:Envelope>\"}"
# → {"status":200,"headers":{...},"body":"<...MultiplyResult>42..."} が返る
