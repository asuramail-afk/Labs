Document / Element / Node — DOMツリーの基本構造

✓ iOS ✓ Android

DOMはツリー構造。documentがルート、すべての要素はNodeを継承。parentNode/children/nextElementSiblingでツリーを辿る。

💡 利用シーン
  1. クリックされた要素の親要素までイベントを「上り」たい(parentNode)
  2. テーブルの全行をchildrenでループし、各セルの値を集計
  3. 同じ階層の次の要素をnextElementSiblingで探してフォーカス移動
document  ← ルート(Documentオブジェクト)
   │
   └─ html
       ├─ head
       └─ body
           ├─ div#app  ← Element(Nodeを継承)
           │   ├─ h1   ← Element
           │   │   └─ "Hello"  ← Text Node
           │   └─ p
           └─ div#footer

▼ ナビゲーション API
parentNode          → 親へ
children            → 子(要素のみ・配列風)
childNodes          → 子(テキストノード含む)
firstElementChild   → 最初の子要素
nextElementSibling  → 次の兄弟要素
📌 NodeとElementの違い
NodeはDOMツリーの全要素の基底型(テキスト・コメント・要素すべて)。Elementはその中で「タグを持つもの」(<div>等)。
テキストノードを除いて要素だけ扱いたい時は children / firstElementChild を使うのが安全。

createElement / appendChild / remove — 要素の生成・追加・削除

✓ iOS ✓ Android

DOM要素はdocument.createElement('div')で空のまま生成し、parent.appendChild(el)でツリーに繋ぐと初めて画面に出る。el.remove()で自身を切り離す。

💡 利用シーン

  2. 「+追加」ボタンでフォーム行を増やす(動的フォーム)
  3. 削除アイコンを押した行をremove()でDOMから消す
①生成        ②属性設定         ③ツリーに挿入
─────       ─────────         ─────────────
const el =  el.textContent     parent.appendChild(el)
  document    = "Item"                  │

insertBefore(el, ref)   → ref の前に追加
el.before(newEl)        → el の直前に追加 (新API)
el.after(newEl)         → el の直後に追加 (新API)

createElementで作っただけの要素は「メモリ上のオブジェクト」で、画面には出ない。親要素のappendChildやappendでDOMツリーに接続して初めて表示される。
切り離した要素は変数で持っていれば再利用可能(別の場所に再挿入できる)。

✓ iOS ✓ Android

💡 利用シーン

el.classList.replace("a","z") ← a を z に差し替え

querySelector / querySelectorAll — CSSセレクタで要素検索

✓ iOS ✓ Android

querySelector('セレクタ')は最初の1個、querySelectorAllは全件(NodeList)。CSSと同じセレクタ記法で書ける。

💡 利用シーン
  1. フォーム内のinput[required]を全件取り、未入力チェック
  2. テーブル行のtr.errorだけを抽出してハイライト
  3. クリックされたボタンの祖先カードをclosest('.card')で取得
▼ 検索系API比較

document.getElementById('id')         → 1件 (idのみ・最速)
document.getElementsByClassName('c')  → HTMLCollection(動的)
document.getElementsByTagName('div')  → HTMLCollection(動的)
document.querySelector('セレクタ')      → 最初の1件
document.querySelectorAll('セレクタ')   → NodeList(静的・スナップショット)

▼ NodeList と HTMLCollection の違い
querySelectorAll → NodeList(forEach使える / 静的)
getElementsBy*   → HTMLCollection(forEach不可 / 動的)

▼ closest: 自分から「上」へセレクタにマッチする最初の祖先
btn.closest('.card')   → ボタンを含むカードを取得
📌 静的(static)と動的(live)コレクションの違い
querySelectorAllの結果は呼出時点のスナップショット。後でDOMが変わっても結果は変わらない。
getElementsByClassNameはDOMの変更が即反映される「ライブコレクション」。ループ中に要素を消すと混乱するので注意。

attributes / dataset — 属性とdata-*の操作

✓ iOS ✓ Android

標準属性はel.idのように直接アクセス、独自属性はdata-*で書いてel.dataset.キーで読み書きする。

💡 利用シーン

  2. OutSystems Wijmo グリッドの行にdata-row-keyを埋め込み行特定
  3. CSSで[data-status="error"]のように属性セレクタでスタイル分岐
HTML側
<button id="btn1"
        data-user-id="42"
        data-action="delete">削除</button>
                                ▼
JS側

▼ 汎用API
btn.getAttribute('data-user-id')      → "42"
btn.setAttribute('data-user-id','99') → 書込
btn.hasAttribute('disabled')          → true/false

数字始まりや大文字始まりは使えない、すべて文字列値(数値も"42"として返る)。

addEventListener / removeEventListener — リスナの登録と解除

✓ iOS ✓ Android

el.addEventListener('click', fn)でイベントを購読、removeEventListener('click', fn)で解除。解除には登録時と同じ関数参照が必要(これがハマりどころ)。

💡 利用シーン
  1. SPA画面遷移前に登録したscrollリスナを解除してメモリリーク防止
  2. once: trueオプションで「初回クリックのみ」反応するボタン
  3. passive: trueでスクロール中のtouchmoveを高速化
▼ 基本形
el.addEventListener('click', handler);
el.removeEventListener('click', handler);   ← 同じ関数参照が必要

▼ よくある罠: アロー関数を直接渡すと解除不能
el.addEventListener('click', () => doX());     ← 参照を保持してない
el.removeEventListener('click', () => doX());  ← 別関数なので解除されない!

▼ 正解: 関数を変数に入れる
const handler = () => doX();
el.addEventListener('click', handler);
el.removeEventListener('click', handler);   ← OK

▼ オプション(第3引数)
{ once: true }    → 1回だけ呼ばれて自動解除
{ passive: true } → preventDefault() 不可だが高速化(スクロール系)
{ capture: true } → キャプチャフェーズで発火 (Lab 07参照)
📌 onClickプロパティ vs addEventListener
el.onclick = fnは1つしか登録できない(上書き)。addEventListenerは同じイベントに何個でも登録可能。現代では基本後者を使う。

Event / CustomEvent — 自作イベントとdetail

✓ iOS ✓ Android

new CustomEvent('名前', { detail: データ })で独自イベント生成、el.dispatchEvent(ev)で発火。detailに任意データを乗せられる。

💡 利用シーン
  1. 子コンポーネントから親に「保存完了しました」を伝える(save:doneイベント)
  2. OutSystemsの自作Block/Web Componentで状態変化を発信
  3. 異なるモジュール間の疎結合な通信(イベントバスパターン)
▼ 標準イベント vs カスタムイベント

標準: el.click()  → "click"イベント発火 (DOMが用意済み)

カスタム:
  // 1. リスナを先に登録
  el.addEventListener('user:login', e => {
    console.log(e.detail.userId);   ← detailで任意データ受取
  });

  // 2. イベント生成
  const ev = new CustomEvent('user:login', {
    detail: { userId: 42, name: 'Tom' },
    bubbles: true   ← 親へ伝搬させたい場合
  });

  // 3. 発火
  el.dispatchEvent(ev);   → リスナが呼ばれる
📌 イベント名の慣例
標準イベント名(click等)と衝突しないよう、コロン区切りの名前空間が広く使われる: app:ready / cart:updated / user:logout。

07

イベント伝搬 — capture / bubble / stopPropagation

✓ iOS ✓ Android

DOMイベントは capture(下り)→ target → bubble(上り)の3フェーズで伝搬する。stopPropagation()で停止、preventDefault()で標準動作キャンセル。

💡 利用シーン
  1. 親要素1つにリスナを登録し、子要素のクリックをイベント委譲で処理(動的追加要素にも効く)
  2. モーダル外クリックで閉じる処理を、内側クリックでstopPropagation()して防ぐ
  3. フォームsubmitをpreventDefault()で止め、JSでバリデーション後に手動送信
▼ イベントの3フェーズ

         ① CAPTURE(下り)
                │
   ┌─ outer ◄──┼──┐
   │   ┌─ middle ◄┐│
   │   │   ┌inner ◄││
   │   │   │  ⚡target  ② TARGET
   │   │   └──────►│
   │   └──────────►│
   └──────────────►│  ③ BUBBLE(上り) ← 通常のリスナはここ

▼ addEventListener の第3引数
addEventListener('click', fn)              → bubbleフェーズで発火 (既定)
addEventListener('click', fn, true)        → captureフェーズで発火
addEventListener('click', fn, {capture:true}) → 同上(オブジェクト形式)

▼ 制御メソッド
e.stopPropagation()            → これ以降の伝搬を止める
e.stopImmediatePropagation()   → 同要素の他リスナも止める
e.preventDefault()             → ブラウザ標準動作キャンセル
                                 (リンク遷移/フォーム送信など)
📌 イベント委譲(delegation)
bubbleを利用した実装パターン。子要素1個ずつにリスナを付ける代わりに、親に1個だけ付けてe.targetで発生元を判定する。動的に追加された子要素にも効く・メモリ効率も良い。
▶ 実機で動かす: 3層ネストでフェーズ確認
外側 (outer)
真ん中 (middle)
⚡ ここをタップ (inner)
準備状態
(未準備)
最後の発火順

JS — 「①リスナ準備」「②真ん中でstop」「リセット」ボタンの中身
let lab7Order = [];
let lab7StopAtMiddle = false;

// 「①リスナ準備」ボタン
function lab7Setup() {
  lab7Reset();
  const outer  = document.getElementById('lab7-outer');
  const middle = document.getElementById('lab7-middle');
  const inner  = document.getElementById('lab7-inner');

  // capture フェーズ(第3引数 true)
  outer.addEventListener('click', () => lab7Order.push('outer:CAPTURE'), true);
  middle.addEventListener('click', (e) => {
    lab7Order.push('middle:CAPTURE');
    if (lab7StopAtMiddle) e.stopPropagation();
  }, true);

  // target & bubble フェーズ
  inner.addEventListener('click', () => lab7Order.push('inner:TARGET'));
  middle.addEventListener('click', () => lab7Order.push('middle:BUBBLE'));
  outer.addEventListener('click', () => {
    lab7Order.push('outer:BUBBLE');
    document.getElementById('lab7-after').textContent = lab7Order.join('\n→ ');
    console.log('発火順: ' + lab7Order.join(' → '));
    lab7Order = [];
  });

  document.getElementById('lab7-before').textContent = '準備完了 (innerをタップ)';
  console.log('リスナ登録完了 — innerをタップしてください');
}

// 「②真ん中でstop」ボタン
function lab7Stop() {
  lab7StopAtMiddle = true;
  console.log('middle でcaptureフェーズで stopPropagation する設定にしました');
}

// 「リセット」ボタン
function lab7Reset() {
  lab7StopAtMiddle = false;
  lab7Order = [];
  document.getElementById('lab7-after').textContent = '(未実行)';
}

AbortController — 複数リスナの一括解除

✓ iOS ✓ Android

addEventListener('click', fn, { signal })でsignalを渡しておくと、controller.abort()1回で全部のリスナを一度に解除できる。fetchのキャンセルも同じAPIで可能。

💡 利用シーン
  1. SPAコンポーネント破棄時に、登録した10個のリスナをabort()1発で解除
  2. 長時間のfetchを5秒でタイムアウト(AbortSignal.timeout(5000))

MutationObserver — DOM変更を非同期監視

✓ iOS ✓ Android

要素の追加・削除・属性変化を非同期で検知。サードパーティ製のDOM変更を監視したり、無限スクロールでの画像遅延読込を補助したりに使える。

const observer = new MutationObserver((mutations) => {

}

observer.observe(targetEl, options);
observer.disconnect();    ← 監視停止

IntersectionObserver — 表示領域に入ったか監視

✓ iOS ✓ Android

要素がビューポート(または親)に入った/出たを非同期で検知。scrollイベントでの位置計算より圧倒的に高速で、無限スクロール・遅延ロード・lazy画像の定番。

💡 利用シーン
  1. SNSの無限スクロール: 末尾の「ロード用要素」が見えたら次ページfetch
  2. imgがビューポートに入った瞬間にsrcを設定して遅延ロード

▼ 仕組み

ビューポート(画面)
┌──────────────────┐
│                  │
│   ┌─ 要素A ─┐    │  ← isIntersecting: true
│   │        │    │     intersectionRatio: 1.0
│   └────────┘    │
└──────────────────┘
   ┌─ 要素B ─┐         ← まだ画面外
   │        │            isIntersecting: false
   └────────┘

▼ コード
const io = new IntersectionObserver((entries) => {

ResizeObserver — 要素のサイズ変化を監視

✓ iOS ✓ Android

要素自身のサイズ変化を検知する。window.resizeと違い「特定の要素」のサイズに反応するため、Wijmo FlexGridの親コンテナサイズが変わった時に再描画する用途などに最適。

💡 利用シーン
  1. OutSystems Wijmo FlexGridの親divサイズ変化時にgrid.invalidate()呼出

▼ window.resize と ResizeObserver の違い

window.addEventListener('resize', ...) → ウィンドウ全体の変化のみ

                                          ウィンドウ操作以外の原因も拾う
                                          (flex/grid/JS書込み等すべて)

const ro = new ResizeObserver((entries) => {

    e.target              ← 監視対象要素
  }
});

class MyCounter extends HTMLElement {
  constructor() {                ← インスタンス化時(プロパティ初期化のみ)
    super();

  }
  connectedCallback() {           ← DOMに繋がれた時 (≒ React mount)
    this.render();
    this.addEventListener('click', () => this.inc());
  }
  disconnectedCallback() {        ← DOMから外れた時 (≒ React unmount)
    // クリーンアップ

  attributeChangedCallback(name, oldVal, newVal) {  ← 属性変化時
    if (name === 'label') this.render();
  }
  static get observedAttributes() { return ['label']; }  ← 監視対象属性

  inc() { this.count++; this.render(); }
  render() { this.textContent = `${this.getAttribute('label')}: ${this.count}`; }
}

Shadow DOM — スタイル/DOM のカプセル化

✓ iOS ✓ Android

el.attachShadow({mode:'open'})で要素内に「外と切り離されたDOM空間」を作る。中のCSSは外に漏れず、外のCSSも(原則)中に効かない。Custom Elementsと組合せてカプセル化されたUIコンポーネントを作る。

💡 利用シーン
  1. 埋め込みウィジェットがホストページのCSSに干渉されないようにする
  2. サードパーティ製Web Componentが提供する内部構造を隠蔽
  3. OutSystems画面に外部UIライブラリを埋め込むときのスタイル衝突防止
▼ Shadow DOM 概念

通常のDOM(Light DOM)
┌──────────────────────────┐
│ <style> .x { color:red } </style>   ← 外側のCSS
│ <div class="x">赤</div>              ← 影響を受ける
│
│ <my-widget>
│   ╔ Shadow Root (隔離空間) ╗
│   ║ <style> .x{color:blue}</style>║  ← 中だけ青
│   ║ <div class="x">青</div>       ║  ← 外の.xは効かない
│   ╚════════════════════════╝
│ </my-widget>
└──────────────────────────┘

▼ コード
const host = document.querySelector('#host');
const root = host.attachShadow({ mode: 'open' });
root.innerHTML = `
  <style> p { color: blue; } </style>
  <p>影の中の段落</p>
`;

▼ open vs closed
mode: 'open'   → host.shadowRoot からアクセス可能
mode: 'closed' → 外部からアクセス不可(完全隠蔽)
📌 「外のCSSは効かない」例外
Shadow DOM内にはcolorやfontの 継承は届く。CSS変数(--xxx)も親から引き継がれるため、テーマ色だけ親から渡してスタイルは中で完結、という構成にできる。
